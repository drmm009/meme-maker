# Meme Creator Studio — detailed architecture notes

> Full feature-by-feature map, moved out of CLAUDE.md to keep it short. Read the section for the area you are working on.

Browser-first meme maker: React 19 + Vite 8, canvas-2D image editor, FFmpeg WASM video export, PWA, wrapped for Android with Capacitor. No backend — everything runs client-side. The gallery persists in IndexedDB (`src/utils/galleryStore.ts`, records shaped and versioned by `src/model/galleryRecord.ts`); settings, favorites and watermark use `localStorage` (`src/utils/storage.js`).

## Commands
- `npm run dev` — Vite dev server on http://localhost:5173
- `npm test` — Vitest (jsdom). Run after every change. Test files share a module cache (`isolate: false`), so a file that mocks a module another test file also loads calls `vi.resetModules()` and imports what it tests with `await import()`.
- `npm run lint` — oxlint
- `npm run typecheck` — TypeScript type check (`tsc`, TypeScript 7; checks `.ts`/`.tsx` files only)
- `npm run build` — production build to `dist/` (also the Capacitor `webDir`)
- `npm run deploy` — publish `dist/` to GitHub Pages
- CI (`.github/workflows/ci.yml`) runs lint, typecheck, test, build on every push.

## Layout
- `src/App.jsx` — top-level view switching (discovery, editor, explore, gallery, social). The editor's Back button returns to the view it was opened from (`editorFrom`: Home, Explore, the layout builder…), or Home when the app opened straight into a maker's link
- `src/components/MemeEditor.jsx` (~240 lines: wiring only; the canvas area is `editor/CanvasStage.jsx`, start-up effects `editor/hooks/useEditorSetup.js`, the selected layer `useActiveLayer.js`, toolbar auto-scroll `useToolbarAutoScroll.js`) and `CanvasEditor.jsx` (~210 lines: wiring only; plain canvas 2D; reads the editor stores) — the image editor. Under `src/components/canvas/`: `render/` (`renderScene` + one painter per layer type; caption blur is painted without ctx.filter in `render/paintLayers.ts` via multi-pass copies for Safari compatibility), `draw/` (pure drawing helpers), `interaction/` (`useCanvasInteraction` holds gesture state and calls the editor's handlers; the maths is pure, tested TypeScript: `layerBoxes.ts` box/handle positions, `hitTest.ts`, `hoverCursor.ts`, `dragMath.ts` rotate/resize/crop/move+snap plus `keepShape` preserving photo proportions on side handles, `freehand.ts`, `geometry.ts`, `drawingHits.ts` (picking, moving and resizing shapes and censor regions), `layerPinch.ts` (two fingers on a layer, the first having gone down on it, scale and turn it, snapping to quarter turns; two fingers elsewhere zoom the view), `viewZoom.ts` (the editor's pinch-zoom and pan, a CSS transform on the canvas wrapper run by `useCanvasView`: two fingers, ctrl + wheel or a trackpad pinch zoom, one finger on empty space or the wheel pans while zoomed, a pill goes back to fit; the meme and export don't change); plus `usePointerListeners`), `media/` (GIF photos and stickers and video photos play: `animatedSources.ts` turns each into a source drawing its current frame into a canvas kept in the image cache under the layer's url, so the painters need nothing new; `useAnimatedLayers` redraws while they play, held still while drawing, and hangs `canvas.animation` (`loopsMs`, `pause`, `resume`, `seek`) on the canvas for the export), `layout/canvasLayout.ts` (canvas size, header/footer bands, layer centres) and `CaptionTextOverlay.jsx`. Always dark, phone layout at every width. `VideoEditor.jsx` is the shell: preview/edit modes, transport row, export. `timeline/` is the centre-playhead scrolling timeline (`TimelinePanel`, `TimelineClip`, pure `timelineMath.js`). `ToolRail.jsx` holds the add tools and swaps to the selected clip's tools. `AddMedia.jsx` holds every way to add media (file pickers plus the shared emoji/sticker/template bottom sheets). `CanvasPreview.jsx` is the Konva preview and sizes itself to its container; its parts are in `preview/` (`CanvasMedia`, `CanvasText`, `GridOverlay`; `previewVideo.js` keeps each clip's hidden `<video>` in step with the playhead; hooks for green screen/filters, GIF frames, text playback, stage fit and in-place text editing), and its decisions are pure and tested in `preview/previewMath.ts` and `nodeMotion.ts`. Preview and export share what they draw: text from `src/utils/textLayer.ts` (`textAttrs`/`textBoxAttrs`; the export draws its text stills with them at output scale), rotation from `src/utils/rotation.ts` (clips turn about their top-left corner like Konva; Rotate turns about the centre; the export rotates with FFmpeg into the same place), and the layout grid lines from `src/utils/gridLines.ts`. Clip and project types are in `src/model/videoProject.ts`. Items carry `hidden`, `muted`, `volume` (0..1) and `fadeInMs`/`fadeOutMs`; preview and FFmpeg export both respect them (`src/utils/audioFades.ts`). Videos append to the end of the main sequence; `splitItem`/`duplicateItem` live in the store. Video items can carry `chromaKey` ({ color, similarity, blend }; color `'auto'` until the preview samples it): `src/utils/chromaKey.js` mirrors FFmpeg's chromakey + despill so the preview matches the export. Text items can carry `animation` ('pop' | 'shake' | 'typewriter'): `src/utils/textAnimation.ts` is the shared model; the preview animates only during playback (paused text rests), and export renders stills per step, with shake done as overlay expressions. GIF stickers are `sticker` items with `isGif`: the preview decodes their frames with `ImageDecoder` (`src/utils/gif.js`) and FFmpeg reads them natively; the Giphy picker uses `src/services/giphy.js` (needs `VITE_GIPHY_API_KEY`). `exportVideoFFmpeg(..., onProgress(percent, { phase, etaSec }), { format: 'gif' | 'mp4', backgroundColor, download })` (`src/utils/ffmpegExport.js`) renders an MP4 or palette GIF and returns `{ blob, fileName }`. MP4s are drawn frame by frame by the preview's own scene (`preview/sceneRenderer.ts`: the same Konva nodes and shared helpers as CanvasPreview, seeking each video per frame) and encoded by the browser at 30fps (`src/utils/webCodecsExport.ts`, WebCodecs through Mediabunny, loaded only when exporting); FFmpeg then only mixes the sound onto the copied picture (`createExportGraph({ encodedVideo })`), and isn't loaded at all for silent projects. GIFs, browsers that can't encode the size, and any failure part-way (not a cancel) use the whole-FFmpeg render instead (`encoder: 'ffmpeg'` forces it); the FFmpeg command itself is built by the pure, tested `src/utils/exportGraph.ts`, and `ffmpegExport.test.js` snapshots the full command for typical projects against a fake FFmpeg, so update those snapshots (`npx vitest -u`) only for intended changes; the editor passes `download: false` and shows `ExportReadyCard` (share sheet or save). `cancelExport()` terminates FFmpeg mid-export. Run every FFmpeg command through `runFFmpeg(ff, args)`: when the engine aborts ("Aborted()" with no return within 1.5 s; the core also prints it as every command exits normally) or a command prints nothing for a minute it terminates that FFmpeg and throws `FFmpegCrashedError`, the next `loadFFmpeg()` makes a fresh one, and the whole-FFmpeg export retries once. Meme effects: freeze frame (`insertFreeze`), reverse/boomerang (`applyClipEffect` swaps in an FFmpeg pre-render from `src/utils/clipEffects.js` and keeps `original`), zoom-punch (`item.punches` in footage ms, `src/utils/zoomPunch.ts`). Slow jobs set the store's `busy` label and never overlap an export. Drawing order (preview and export) comes from `src/utils/layerOrder.ts` (video < photo < sticker < text, overridden by `item.z` via `moveLayer`). Colour filters (`item.filter`, `src/utils/clipFilters.ts`: canvas CSS filter in the preview, colorchannelmixer + lutrgb in export), transitions (`item.transitionIn` on the incoming clip, `src/utils/clipTransitions.ts`), voiceovers (`src/utils/voiceRecorder.js`, audio items keep `mimeType` so export names the file right), and export `resolution` 720 or 1080. Timeline filmstrips come from `src/utils/filmstrip.js` (frames cached per URL, not stored in the project). The project auto-saves to IndexedDB (`src/utils/videoDraftStore.ts`, its own `meme-creator-video` database, uploaded files stored as Blobs; drafts carry `VIDEO_PROJECT_VERSION` and are upgraded by `migrateVideoProject` on load) and `useVideoDraft` offers to restore it. Auto captions (Text > Captions): `src/workers/whisper.worker.js` runs Whisper tiny.en (transformers.js, imported from jsDelivr at a pinned version so its ONNX WASM isn't bundled; model cached by the browser) via `src/utils/transcriber.js`; `src/utils/clipAudio.js` pulls 16 kHz mono audio from heard videos and voiceovers; `src/utils/captionChunks.js` groups words into 2-4 word captions and styles them (classic, creator, typewriter). Captions are text items with `autoCaption: true` (`setAutoCaptions`/`restyleAutoCaptions`/`removeAutoCaptions`), share one timeline row, and export as a single concat image sequence (`src/utils/captionTrack.ts`) instead of one FFmpeg input each.

## Conventions
- New code in TypeScript (`.ts`/`.tsx`, strict); existing `.js`/`.jsx` is converted file by file (with `git mv` so history follows). Plain CSS files next to components.
- Saved data carries a format version (gallery records, video drafts). When its shape changes, bump the version in `src/model/` and teach that model's migrate function to upgrade the previous version, so saved memes and drafts keep opening.
- `vite.config.js` uses `base: './'` so builds work under GitHub Pages and Capacitor — keep asset paths relative.
- Heavy libs (FFmpeg, MediaPipe, background removal) load lazily at runtime; don't import them eagerly.
- Optional env: `VITE_GIPHY_API_KEY` (see `.env.example`). Gemini keys are user-supplied in-app — never hardcode keys.
