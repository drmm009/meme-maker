# Meme Creator Studio — detailed architecture notes

> Full feature-by-feature map, moved out of CLAUDE.md to keep it short. Read the section for the area you are working on.

Browser-first meme maker: React 19 + Vite 8, canvas-2D image editor, FFmpeg WASM video export, PWA, wrapped for Android with Capacitor. No backend — everything runs client-side. The gallery persists in IndexedDB (`src/utils/galleryStore.ts`, records shaped and versioned by `src/model/galleryRecord.ts`); videos saved to My Studio live in the video editor's own database (`src/utils/videoDraftStore.ts`); settings, favorites and watermark use `localStorage` (`src/utils/storage.js`). Every write to the video database goes through one queue (`serially` in `videoDraftStore.ts`): auto-saves every 700ms can overlap a slow one, and a save's clean-up of unused files (`dropUnusedMedia`) must never run between another save storing a clip and listing it; a clip whose blob: link can't be read is skipped rather than stopping the save. Saving to My Studio (App's `handleSaveToGallery`, from the image editor, sticker maker and GIF maker) waits for IndexedDB and resolves true or false: the image editor celebrates only once it's stored and otherwise shows a red note over the canvas (`pasteToast`), and the GIF maker a red line under its buttons. The PWA's service worker precaches the app (about 2.5 MB) but not the wasm engines, FFmpeg's core script or the emoji list (`data-*`); those, like every built file, are kept in the `lazy-chunks` cache once loaded (`vite.config.js`).

## Commands
- `npm run dev` — Vite dev server on http://localhost:5173
- `npm test` — Vitest (jsdom). Run after every change. Test files share a module cache (`isolate: false`), so a file that mocks a module another test file also loads calls `vi.resetModules()` and imports what it tests with `await import()`.
- `npm run lint` — oxlint
- `npm run typecheck` — TypeScript type check (`tsc`, TypeScript 7; checks `.ts`/`.tsx` files only)
- `npm run build` — production build to `dist/` (also the Capacitor `webDir`)
- `npm run deploy` — publish `dist/` to GitHub Pages
- CI (`.github/workflows/ci.yml`) runs lint, typecheck, test, build on every push.

A photo mostly of people also runs the selfie multiclass model (People), and `subjectConfidence` takes people from it plus every separate blob General found (`blobs`) that the People model doesn't see as a person (under 30% overlap), since DeepLab sometimes calls a pet beside a person a person; otherwise General's mask. `edgeAlpha` makes the edge, the mask is stretched smoothly over the photo (up to 2048 px) with a little blur, and the result is a WebP (lossless alpha, about ten times faster to encode than PNG; PNG where the browser can't write WebP) the photo's size. Nothing found (under 0.5% of the picture, as with drawings and comics): `NoSubjectError`, whose message is shown as it is. ## Conventions
- New code in TypeScript (`.ts`/`.tsx`, strict); existing `.js`/`.jsx` is converted file by file (with `git mv` so history follows). Plain CSS files next to components.
- Saved data carries a format version (gallery records, video drafts). When its shape changes, bump the version in `src/model/` and teach that model's migrate function to upgrade the previous version, so saved memes and drafts keep opening.
- `vite.config.js` uses `base: './'` so builds work under GitHub Pages and Capacitor — keep asset paths relative.
- Heavy libs (FFmpeg, MediaPipe, background removal) load lazily at runtime; don't import them eagerly.
- Optional env: `VITE_GIPHY_API_KEY` (see `.env.example`). Never hardcode keys. AI captions come from the built-in library until a backend writes them. Without a Giphy key, the Stickers sheet's Animated and GIFs tabs (`GiphyResults.tsx`) tell the developer to add one (`import.meta.env.DEV`) and anyone else that they aren't available yet; the same goes for Face swap without `face_swap_server.py` (`FaceSwapStudio.tsx`, the video editor's `FaceSwapPanel.tsx`, `FaceMorphModal.jsx`) and for social media links without the link helper (`VideoLinkPanel.tsx`: save the video and add it with Upload; a direct video file link works).
